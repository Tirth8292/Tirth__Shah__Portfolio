Olist Marketplace Analytics Engineering Platform

Analytics Engineering 2026 Python · FastAPI · PostgreSQL · Power BI

The Problem

Raw e-commerce data usually lives in disconnected CSV exports — orders, payments, reviews, sellers — so nobody can answer a business question without manually re-joining files every time. I took Olist's real Brazilian marketplace dataset and turned it into a proper analytics system: a modeled warehouse, engineered business metrics, and live APIs that serve those metrics on demand — not a one-off notebook.

Five-Stage Pipeline

  • Ingest — Python loads all 9 raw CSVs into SQLite (same code path targets Postgres/Supabase in production).
  • Stage — SQL cleans and types every field: timestamps, prices, lat/long, lowercase cities, English category names.
  • Model — Star schema: dim_customers, dim_sellers, dim_products, dim_dates + fact tables with GMV, delivery days, late-delivery flags.
  • Analyze — Reusable SQL views answer common questions without re-joining raw tables.
  • Serve — Seller scores, RFM segments, cohort retention, and delivery-lane CSVs consumed by both API and Power BI.

Key Models

  • Seller Score (0–100): 40% on-time delivery + 30% avg review score + 20% (1 − cancellation rate) + 10% revenue growth. All 3,095 sellers bucketed into low_risk / watchlist / high_risk.
  • Customer RFM: Recency, frequency, monetary value classifies ~93,000 customers into champions / loyal / recent / at_risk / needs_attention, feeding a 219-row monthly cohort-retention table.

Why It Isn't "Just a Notebook" — The API Layer

  • Main Analytics API (port 8000) — seller scoring, leaderboard, delivery estimates, repeat-orders-by-city, product/order/seller lookups.
  • Live Ingestor Portal (port 8001) — add new records and re-trigger the pipeline without touching the database directly.
  • Dashboard API (port 8002) — sales summary, category/trend/payment breakdowns, geo sales map, and filter options for a front-end dashboard.

Production Upgrade Path

Runs on SQLite locally (zero cloud credentials to clone), but ships dbt models with tests & lineage, an Airflow DAG for scheduled orchestration, and a docker-compose Postgres setup — the same design maps directly onto a real production stack.

Algo Trade Strategy

Quantitative Research 2025–2026 Python · OHLCV · Backtesting · Options

The Problem

Intraday options trading can generate frequent price movements, but many moves lack sufficient volume confirmation. This project was developed to identify stronger directional opportunities by combining 1-minute candle-body movement with trading volume, while applying strict intraday risk-management rules.

254
Market Sessions
290

69.7%

01 Aug 2025 – 25 Aug 2026 · 202 Target Exits · 88 Stop-Loss Exits · 3 Lots per Simulated Trade

Strategy Workflow

  • Market Selection — Selects NIFTY or SENSEX based on the weekday and weekly expiry schedule. The strategy avoids expiry-day trading and does not trade on Friday under the current rule set.
  • Reference Window — From 10:00 AM to 10:45 AM, analyses every 1-minute OHLCV candle and records the strongest bullish and bearish reference candles using candle-body size and volume.
  • Signal Detection — From 10:45 AM to 2:55 PM, enters a Call when a green candle exceeds the bullish reference in volume and body strength. Enters a Put when a red candle exceeds the bearish reference.
  • Strike Selection — Uses the underlying spot price to select a near-at-the-money NIFTY or SENSEX option contract for the selected direction.
  • Entry Control — Limits repeated entries per direction to reduce overtrading and prevent uncontrolled signal repetition.

Risk-Management Engine

  • Initial Protection: Every simulated trade receives an instrument-specific stop-loss and profit-target structure at entry.
  • Break-Even Rule: After the first target is reached, the stop-loss moves to the entry price to protect the position from turning negative.
  • Trailing Exit: The stop-loss trails favourable price movement to protect profit while allowing strong intraday moves to continue.
  • SENSEX Peak Rule: High-volume SENSEX signals track peak unrealised profit and exit if the profit retraces below 90% of that peak.
  • End-of-Day Exit: All open positions are closed at 2:55 PM to avoid overnight options exposure.

Technical Implementation

The prototype is implemented in Python as a CSV-driven paper-backtesting workflow. It processes 1-minute OHLCV data, creates reference benchmarks, detects qualifying signals, manages simulated positions, and records entry, exit, stop-loss, target, and profit/loss events. A TradingView/Pine Script version is being developed for visual validation and forward testing.

Note: Results are based on historical analysis. They are not live audited performance, do not guarantee future returns, and are not investment advice.

KissanMitra – AI-Based Smart Farming Solution

AI / Smart Farming IBM Hackathon 2025 React · Vite · Firebase

The Problem

Generic weather apps show raw numbers — temperature, humidity, rainfall — without telling a farmer what that means for irrigation, spraying, or harvest timing. KissanMitra converts live weather, soil, and crop data into farmer-facing decisions, in the farmer's own language (English, Hindi, or Gujarati). Built and submitted during the IBM SkillsBuild AI-ML Innovation Hackathon.

12
Indian Crops Supported
5-tier
API Fallback Chain
3
Languages (EN/HI/GU)

Core Modules

  • Real-time Weather, 5-Tier Fallback: OpenWeatherMap (primary) → OpenWeatherMap (backup) → WeatherAPI → StormGlass → Open-Meteo → offline mock. The app never shows a blank screen, even if every paid API quota is exhausted.
  • Live Soil Analysis: pH, nitrogen, organic carbon, and texture from ISRIC SoilGrids + real-time moisture from Open-Meteo. Regional naming maps texture + India lat/lon bands to local soil types (Black Cotton Soil, Alluvial Soil, Desert Soil).
  • Rule-Based Crop Health Engine: 12 crops with ideal pH/temperature/moisture/rainfall bands and month-based growth-stage calendars. Produces a 0–100 health score, Low/Medium/High risk tier, and plain-language breakdown.
  • Alerts & Daily Actions: Translates raw metrics into simplified warnings and a ready-made task checklist (irrigate, spray, hold off, harvest window).
  • Marketplace Tab: Firebase Firestore-backed listings with haversine-distance nearby-shop calculation, falling back to bundled demo data when Firebase isn't configured.
  • Full i18n: English, Hindi, Gujarati — including native-script digit rendering (०–९, ૦–૯), not just translated labels.
  • PWA & UX: Installable app shell, dark mode, and geolocation auto-detection with last-known-location caching.

Key Design Decision

Every data source degrades gracefully — the mock/live switch happens once, at the bottom of the stack, and every UI component above it is unaware which mode it's in. That's a fallback-first service layer, not "added mock data for a demo." The crop-health module is a rule-based agronomic scoring engine — deterministic penalty math — not a trained ML model.

PharmaLink is a full-stack healthcare platform connecting patients and doctors through separate, role-based portals. Built and presented at MECIA HACK 2.0 at SVIT. The customer portal lets users discover doctors, book appointments, order medicines, schedule lab tests, upload prescriptions, manage subscriptions, and track orders — all from a unified dashboard.

Key Features

  • Role-Based Authentication: Separate patient and doctor login/signup flows with protected dashboards and role-based navigation.
  • Doctor Appointment System: Search doctors by city and specialization, view availability, generate time slots, and book appointments with real-time slot updates.
  • Medicine & Prescription Management: Browse medicines, manage cart and quantities, place orders, upload prescriptions, and receive medicine suggestions.
  • Lab & Healthcare Services: View available diagnostic labs and supported medical tests from the customer dashboard.
  • Order & Delivery Tracking: Complete order workflow with checkout, delivery address, estimated delivery, status updates, and dedicated tracking.
  • Doctor Management Portal: Doctors update their profile, availability, working hours, slot duration, and individual appointment slots.
